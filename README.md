# TCGA Mobile

A browser extension that makes [TCG Arena](https://www.tcg-arena.fr) usable on phones. TCG Arena does not
officially support mobile; this extension injects CSS and a little JavaScript to hide the chat / game log,
the top navigation bar, the lobby's "1. Learn / 2. Connect / 3. Play" walkthrough and other desktop-only chrome, shrink the side bar and stop accidental zooming, so the board fits a phone screen.

It ships as **two builds from one shared source**:

| Platform | Browser | Manifest | How it reaches users |
|---|---|---|---|
| iOS / iPadOS | Safari | V3 | A Safari Web Extension wrapped in an iOS app, distributed through the App Store (or TestFlight / a dev build on your own device). |
| Android | Firefox | V2 | Signed and listed on addons.mozilla.org (AMO) with `gecko_android` set, or side-loaded via `web-ext run` for development. |

Chrome, Edge and Samsung Internet on Android do not run extensions, and iOS only allows extensions through
Safari, so Safari + Firefox is the whole mobile story.

## Why these choices

- **Safari on iOS** only loads extensions that are bundled inside a native app built with Xcode. Apple's
  `safari-web-extension-converter` generates that app from a normal WebExtension folder. iOS requires a
  non-persistent background page (we have no background script at all, so that is moot) and users grant
  the extension access to `tcg-arena.fr` from Safari's `aA` menu the first time it runs.
- **Firefox for Android** has an open extension ecosystem since Firefox 120. Mozilla still recommends
  Manifest V2 there because MV3 event pages and host-permission prompts have rough edges on Android, and
  V2 extensions are still accepted on AMO. The manifest must include `browser_specific_settings.gecko_android`
  or AMO will list it as desktop-only. `browserAction` popups work on Android.
- **No background script, no host-permission surprises.** Everything is a declarative content script
  (`content_scripts` matching `*://*.tcg-arena.fr/*`) plus `storage` for settings, which behaves identically
  in both browsers.
- **TCG Arena blocks portrait, not phones.** In portrait it renders only a "desktop in landscape mode" notice; in landscape the full app loads on a phone. The extension therefore only needs to fix the landscape layout.
- **TCG Arena's DOM is friendly.** It is a React + Vite app using Bootstrap with stable, human-readable
  class names (`.game`, `.history` for the chat/log panel, `.chatbox`, `.left-bar`, `.navbar`,
  `.hand-board-section`, `.player-section`...). The game route is `/play`. The site already adds
  `body.mobile` when it detects a coarse pointer, and we build on top of that rather than fighting it.

## Layout

```
src/                       shared extension source (what both builds ship)
  content/tcga-mobile.css  all visual changes, gated on html.tcgam + per-feature classes
  content/tcga-mobile.js   applies settings as <html> classes, viewport fix, floating menu, portrait hint
  shared/settings.js       settings schema + storage helpers (used by content script and popup)
  popup/                   toolbar popup with the same toggles
  icons/                   generated by scripts/make-icons.mjs
manifests/
  manifest.safari.json     MV3
  manifest.firefox.json    MV2 + gecko / gecko_android
scripts/build.mjs          copies src/ + the right manifest into dist/<target>/
safari/                    Xcode project generated by `npm run safari:convert` (references dist/safari)
```

Features are toggled from the popup or from the floating `☰` button on the board (easier to reach on iOS
than the extension popup). Every toggle is an `html.tcgam-<key>` class so it applies live without a reload.
Setting keys must never collide with the UI element classes (`tcgam-ui-*`): a setting named `fab` once put
`tcgam-fab` on `<html>` and the button's `display: none` rule hid the whole page.

**Virtual screen width.** TCG Arena is laid out for a 1200px+ desktop viewport: the board is sized in `vh`,
but text and Bootstrap spacing are in `rem`. At a phone's real CSS width (~840px landscape) the text is huge
relative to the board and everything looks cramped. The "Virtual screen width" setting (default 1280) sets
`<meta name=viewport content="width=1280">` so the browser lays the page out like a small desktop and scales
it down. Firefox for Android ignores that meta while in fullscreen, so there the content script scales the
root `font-size` by `deviceWidth / virtualWidth` instead (`html.tcgam-fsscale`), which shrinks rem-based text
and spacing while the vh-based board keeps filling the screen. Root `zoom` was tried and rejected: Firefox
scales viewport units under zoom, so the board shrank to two thirds of the screen.

**Side drawer.** The game's left bar (turn timer, pass turn, undo, dice, settings...) is 64px wide with 16px
buttons on a phone. With "Side bar as a slide-out drawer" it is taken out of the board's flex row, hidden
off-screen, and opened from a handle on the left edge (`.tcgam-ui-handle`); tapping anywhere outside closes
it. Its sizes are in `vh` on purpose: 1 CSS px is a different physical size in the virtual-width layout
than in fullscreen, but 1vh is the same screen fraction in both, so buttons stay finger-sized (10vh tall).

**Full-width board and the stack column.** The site reserves a 32vh column on the right for the chat panel
and the "stack" (cards being played/resolved), via inline `padding-right: 32vh` on the board containers plus
`calc(100vw - 32vh - 5rem)` zone widths. Chat is an overlay here, so the reservation is cut to 10vh and the
zones widened accordingly. Stack card positions are computed and stored by the site's JavaScript (inline
`transform: translate(x, y)`), so they cannot be re-laid out with CSS; instead a CSS `translate: 70% 0`
(which composes with `transform`) pushes them off the right edge so 30% peeks in. The first tap on a
peeking card slides the column in (`html.tcgam-stack-open`) and is swallowed so the card menu does not open;
tapping anywhere else slides it back out.

**On-screen controls.** Drawer handle top-left (the site's own token palette sits at left-middle) showing the
turn number and turn timer mirrored from the hidden bar; quick-menu button top-right with its panel below
it; chat and quick-reaction buttons bottom-right. The chat opens as a large overlay sized to the *visual* viewport (`--tcgam-vvh`, tracked from
`window.visualViewport`), so when the on-screen keyboard is up the panel shrinks and the input stays above
it. Only the height is used: Firefox Android reports a `visualViewport.offsetTop` while the keyboard is open
that it does not actually render for fixed elements. Chat type is in `vh` so it is the same physical size in
every layout mode; Bootstrap's `end-0`/`bottom-0` on `.history` are `!important` and need `!important` to
override. The reaction row is a
child of `.history` in the site's DOM, so the "reactions" button keeps `.history` rendered but invisible and
floats just the `.emoji-row` at the bottom of the screen; if the site's own quick-emoji toggle is off it is
clicked once so the row exists.

**Fullscreen.** The browser's own toolbar can only be hidden through the Fullscreen API, which needs a user
gesture, so the first tap inside a game requests it (toggle: "Fullscreen on first tap"). Works on Firefox for
Android. On iPhone the Fullscreen API for page elements only exists since Safari 17.2 (iOS 17.2); older
iPhones will ignore it, and Safari's own toolbar still shrinks when you scroll.

## Development

```sh
npm install
npm run build            # dist/firefox and dist/safari
npm run lint:firefox     # web-ext lint on the Firefox build
```

### Firefox desktop (fast iteration)

```sh
npm run run:firefox      # opens Firefox with the extension loaded on /play
```

### Firefox for Android (device or emulator)

1. Install Firefox (or Firefox Nightly) on the phone/emulator, enable USB debugging, `adb devices`.
2. In Firefox on the device: Settings → About Firefox → tap the logo 5 times, then Settings → Remote debugging via USB.
3. `ADB_DEVICE=<id from adb devices> npm run run:android` (e.g. `emulator-5554`; use `--firefox-apk org.mozilla.fenix`
   for Nightly instead of `org.mozilla.firefox`). Leave it running: it installs a *temporary* add-on that
   disappears when Firefox restarts, and it hot-reloads the add-on whenever `dist/firefox` changes, so run
   `npm run build:firefox` after editing `src/`. Reload the page afterwards.
4. Force landscape on an emulator: `adb shell settings put system accelerometer_rotation 0; adb shell settings put system user_rotation 1`.
5. `web-ext` prints a TCP port for Firefox's remote debugging protocol; `scripts/rdp.mjs <port> '<js>'` evaluates JS
   in the TCG Arena tab, which is how the layout was verified without a screen in front of you.

### Safari on iOS

```sh
npm run safari:convert   # one-time: generates safari/TCGA Mobile.xcodeproj (iOS-only)
open "safari/TCGA Mobile/TCGA Mobile.xcodeproj"
```

In Xcode set your team on both targets, pick your iPhone, run. Then on the phone: Settings → Apps → Safari →
Extensions → TCGA Mobile → enable and allow `tcg-arena.fr`. After editing `src/`, run `npm run build:safari`
and rebuild in Xcode; the project references `dist/safari` directly. To test on the Mac without a device,
convert without `--ios-only` or enable *Allow unsigned extensions* in Safari's Develop menu.

## Publishing

- **Firefox / Android:** `npm run package:firefox`, then upload `web-ext-artifacts/*.zip` to
  https://addons.mozilla.org/developers/. Keep the `gecko.id` in `manifests/manifest.firefox.json` stable.
- **Safari / iOS:** archive in Xcode and submit through App Store Connect. Requires the Apple Developer
  Program. Bump `version` in `package.json` (the build script writes it into both manifests) and the
  marketing version in Xcode together.

## Known gaps / next steps

- Verified on Firefox for Android (Pixel 9a and an API 34 emulator): chat/log hidden, side bar compact, board
  fills the screen in fullscreen. The in-game board itself (with a deck loaded) still needs a look on a device.
- Firefox content scripts: `window` is the page, `globalThis` is the sandbox. Shared globals must be read
  via `globalThis`, and never cache `document.documentElement` at `document_start`.
- `100dvh` and `:has()` need iOS 15.4+/Safari 15.4+ and Firefox 121+; both are far below what phones run today.
- The site's own `.mobile` mode already moves right-click menus to a centered modal; if it changes class
  names in a release, `src/content/tcga-mobile.css` is the only file to update.
